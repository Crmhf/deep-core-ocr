# Deep Core OCR 最佳实践

本文汇总 Deep Core OCR 在实际使用中的最佳实践，帮助用户获得更稳定、更准确的识别结果。

## 一、核心原则

### 1. 先判断任务类型，再选模型

```
只需要文字 → DeepSeek-OCR（纯 OCR）
需要理解图片再提取文字 → Qwen2.5-VL / MiniMax-M3（视觉理解）
复杂实景 / 兜底 → MiniMax-M3
```

### 2. 按场景选模型

| 场景 | 任务类型 | 推荐模型 |
|------|---------|---------|
| 纸质文档 / 印刷体 / 票据 | 纯 OCR | DeepSeek-OCR |
| 桌面截图 / 客户端界面 | OCR + 视觉理解 | Qwen2.5-VL |
| 实物影像 / 铭牌 / 标签 | 视觉理解 + OCR | Qwen2.5-VL / MiniMax-M3 |
| 网页 UI 文案合规校验 | 纯 OCR | DeepSeek-OCR / Qwen2.5-VL |
| 证件 / 发票 / 票据 | OCR + 版式理解 | Qwen2.5-VL / MiniMax-M3 |

### 3. 先 OCR 后整理

OCR / 视觉理解负责把图片转成文字或结构化信息；大模型负责纠错、归类、结构化。不要期望一步输出完美结果。

### 4. 图片质量决定识别质量

再强的模型也无法识别完全模糊、过度曝光、严重倾斜的图片。

## 二、图像采集建议

### 通用建议

- **光线均匀**：避免阴影、反光、过曝
- **画面平整**：尽量正对拍摄，减少透视变形
- **分辨率充足**：文字高度建议不低于 20 像素
- **完整取景**：保留必要的上下文和边框

### 纸质文档

- 使用扫描仪优先于手机拍摄
- 手机拍摄时，让文档占满画面，四边对齐
- 避免手指、阴影遮挡文字

### 桌面截图

- 使用系统截图工具，保存为 PNG 避免压缩
- 确保关键信息完整显示，不要截断
- 对弹窗单独截图，避免背景干扰

### 实物影像

- 近距离拍摄，让文字区域占画面 50% 以上
- 使用微距模式提高清晰度
- 纯色背景最佳，避免杂乱背景

### 网页 UI

- 全屏截图，包含顶部导航和底部声明
- 对弹窗、悬浮提示单独截图
- 保留 1:1 像素比例，不要缩放

## 三、Prompt 最佳实践

- 明确任务："识别文字"、"提取字段"、"输出 JSON"
- 指定格式：需要 JSON 时给出字段模板
- 约束输出："不要解释"、"不要总结"、"保持原样"
- 参考 [OCR Prompt 编写指南](ocr-prompt-guide.md)

## 四、输出后处理

### 1. 文本清洗

- 去除多余空格、换行
- 合并被错误拆分的单词
- 修正常见 OCR 错误（如 `0` 和 `O`，`1` 和 `l`）

### 2. 结构化校验

- 日期格式统一为 `YYYY-MM-DD`
- 金额统一保留两位小数
- 身份证、手机号等字段做正则校验

### 3. 人工抽检

关键业务字段（金额、身份证号、发票号码）建议人工抽检。

## 五、成本控制

- 80% 日常任务使用 DeepSeek-OCR / Qwen2.5-VL（douzimi 端点）
- 15% 复杂场景使用 MiniMax-M3
- 批量处理时设置合理超时，避免长时间等待
- 对低质量图片先预处理，减少重试

## 六、错误处理与降级

- 当默认提供商失败时，脚本会自动按 `fallback_order` 切换
- 如果所有提供商都失败，检查：
  - API Key 是否正确
  - 网络连接是否正常
  - 端点是否支持当前模型
  - 是否触发速率限制

## 七、安全与合规

- `config.json` 包含 API Key，已加入 `.gitignore`，请勿提交
- 敏感证件图片处理需遵守数据安全规范
- 网页文案合规校验需结合业务规则，OCR 仅提供文本支撑

## 八、与其他工具配合

- **Pillow / OpenCV**：图片预处理（旋转、裁剪、增强）
- **大模型（Claude / GPT）**：文本纠错、结构化、摘要
- **docx / markdown-tools**：生成最终文档
- **正则表达式 / JSON Schema**：字段校验

## 九、推荐工作流

```
1. 采集图片
2. 预处理（可选：旋转、裁剪、增强）
3. 调用 Deep Core OCR
4. 获取原始文字
5. 大模型整理 / 结构化
6. 字段校验与人工抽检
7. 落地到文档 / 表格 / 数据库
```

## 十、常见问题

### Q1：识别结果有乱码怎么办？

- 检查图片编码和分辨率
- 尝试更换模型（如从 DeepSeek-OCR 换到 Qwen2.5-VL）
- 优化 Prompt，明确要求保持原样

### Q2：结构化输出格式不稳定怎么办？

- 在 Prompt 中给出完整 JSON 模板
- 使用 `--mode structured` 并明确字段名
- 输出后用 JSON Schema 校验

### Q3：如何批量处理大量图片？

- 编写 shell / Python 循环调用 `scripts/ocr.py`
- 设置合理的并发数和超时
- 保存中间结果，便于失败重跑

### Q4：douzimi 端点返回 401 怎么办？

- 确认 API Key 是否拥有该模型调用权限
- 确认模型名称是否正确
- 尝试使用 deep-core-image 中可用的 key 进行交叉验证
